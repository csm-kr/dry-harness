# Issues and unresolved decisions

Status: no project-specific issues recorded by this template.

Record an issue when it changes the next action: ID, phase/step, reproduction or missing condition, impact, owner/action, status and resolution evidence. Runtime state and logs remain the first source for execution failures.

For user-only decisions, identify dependent work and what can continue independently. For repeated failures, capture the shared cause and smallest useful fix. Do not convert an issue into a permanent rule solely because it occurred three times.
