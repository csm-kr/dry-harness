# Product requirements

Status: awaiting project-specific planning. This template does not assert product decisions.

## Product and problem
Record the product, intended user, problem, and measurable outcome from the user's input.

## Scope
List confirmed capabilities and explicit exclusions. Link each capability to a requirement ID in the phase contract or a dedicated SPEC document when needed.

## Decisions and open questions
Distinguish explicit user decisions from implementation choices. Put unresolved product decisions in [ISSUES.md](ISSUES.md), with which work they block. Do not re-ask settled decisions.

## Acceptance
Define observable success, important failure behavior, and the evidence required. User paths belong in [USER_FLOW.md](USER_FLOW.md).
